# Sky Take Out 项目架构文档

## 📋 项目概览

**项目名称**: Sky Take Out (苍穹外卖)
**项目类型**: Spring Boot + 前后端分离的外卖订餐平台
**架构模式**: Maven多模块 + 分层架构 + RESTful API
**技术栈**: Spring Boot 2.7.3 + MySQL + Redis + WebSocket + 微信支付

## 🏛️ Maven 模块架构

```
sky-take-out/
├── sky-common/           # 公共模块
├── sky-pojo/            # 数据传输对象模块
├── sky-server/          # 主服务模块
└── pom.xml              # 父POM文件
```

### 1. sky-common (公共模块)
**身份**: 基础工具和通用功能提供者
**作用**: 提供整个项目的基础设施支持

**主要组件**:
- `utils/` - 工具类包
- `properties/` - 配置属性类
- `constant/` - 常量定义
- `context/` - 上下文管理
- `exception/` - 异常定义
- `annotation/` - 自定义注解
- `interceptor/` - 拦截器

**核心类**:
```java
// 上下文管理
BaseContext          // 当前用户上下文
UserContextUtil       // 用户ID管理工具类 (新增)

// 工具类
AliOssUtil          // 阿里云OSS文件上传
WeChatPayUtil        // 微信支付工具
HttpClientUtil        // HTTP请求工具
WebSocketMessageUtil  // WebSocket消息推送工具类 (新增)
RedisConfiguration    // Redis配置

// 拦截器
JwtTokenUserInterceptor // 用户端JWT拦截器
JwtTokenAdminInterceptor// 管理端JWT拦截器
```

### 2. sky-pojo (数据传输对象模块)
**身份**: 数据传输和实体对象定义模块
**作用**: 定义项目中所有的数据传输对象和实体类

**主要组件**:
- `entity/` - 实体类 (数据库表映射)
- `dto/` - 数据传输对象
- `vo/` - 视图对象

**核心类**:
```java
// Entity (数据库实体)
User, Employee, Dish, Setmeal, Category
Orders, OrderDetail, ShoppingCart, AddressBook

// DTO (数据传输)
OrdersSubmitDTO, OrdersPaymentDTO, DishDTO, EmployeeDTO

// VO (视图对象)
OrderVO, OrderSubmitVO, OrderPaymentVO, DishVO, EmployeeVO
```

### 3. sky-server (主服务模块)
**身份**: 核心业务逻辑处理和API提供者
**作用**: 提供RESTful API服务，处理所有业务逻辑

**主要组件**:
- `controller/` - 控制器层
- `service/` - 服务层
- `mapper/` - 数据访问层
- `websocket/` - WebSocket服务
- `task/` - 定时任务

## 🎯 核心业务流程

### 1. 用户下单流程
```
用户端应用
    │ 1. 选择菜品加入购物车
    ▼
Controller: ShoppingCartController.add()
    │ 2. 验证用户状态，添加购物车
    ▼
Service: ShoppingCartServiceImpl.add()
    │ 3. 数据验证，数据库操作
    ▼
Mapper: ShoppingCartMapper.insert()
    │ 4. 持久化购物车数据
    ▼
    │ 5. 返回操作结果
```

### 2. 订单支付流程
```
用户端应用
    │ 1. 提交订单，选择支付方式
    ▼
Controller: OrderController.payment()
    │ 2. 生成支付参数
    ▼
Service: OrderServiceImpl.payment()
    │ 3. 调用微信支付API
    ▼
WeChatPayUtil.pay()
    │ 4. 微信支付处理
    ▼
    │ 5. 返回支付参数给前端
    ▼
前端调用微信支付
    │ 6. 用户完成支付
    ▼
微信支付回调 → OrderController.paymentNotify()
    │ 7. 验证支付结果，更新订单状态
    ▼
WebSocket推送消息 → 管理端显示新订单
```

### 3. 订单状态流转
```
订单状态枚举:
┌─────────────┬─────────────┬─────────────┬─────────────┬─────────────┬─────────────┐
│   1 待付款   │   2 待接单   │   3 已接单   │   4 派送中  │   5 已完成   │   6 已取消   │
│  PENDING_PAY │  WAIT_CONFIRM │  CONFIRMED   │ DELIVERY_ING│  COMPLETED  │  CANCELLED   │
└─────────────┴─────────────┴─────────────┴─────────────┴─────────────┴─────────────┘

状态流转规则:
1 → 2: 用户支付成功
2 → 3: 商家接单
2 → 6: 商家拒单
3 → 4: 开始派送
4 → 5: 送达完成
1 → 6: 用户取消 (未支付)
3 → 6: 商家取消 (特殊情况)
```

### 4. 异常处理组件 (GlobalExceptionHandler)
```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(SQLException.class)
    public Result<String> handleSQLException(SQLException e) {
        log.error("数据库异常: {}", e.getMessage());
        return Result.error("数据库操作失败");
    }

    @ExceptionHandler(BusinessException.class)
    public Result<String> handleBusinessException(BusinessException e) {
        log.error("业务异常: {}", e.getMessage());
        return Result.error(e.getMessage());
    }
}
```

## 🔄 请求处理生命周期

### 完整的API请求流程
```
1. 客户端发起HTTP请求
   ↓
2. CORS处理器处理跨域
   ↓
3. JWT拦截器验证身份
   ↓
4. 全局异常处理器准备
   ↓
5. Controller接收请求参数
   ↓
6. 参数验证 (Bean Validation)
   ↓
7. Service业务逻辑处理
   ↓
8. Mapper数据库操作
   ↓
9. Redis缓存操作 (可选)
   ↓
10. 外部服务调用 (支付、OSS等)
    ↓
11. WebSocket实时推送 (可选)
    ↓
12. Result包装返回结果
    ↓
13. 客户端接收响应
```

## 📈 性能优化策略
